# Temu Open API: перевірка

Практика під проєкти на кшталт «Temu → OpenCart → SAP» (Freelancehunt, 05.10.2026).
Ключів продавця немає, тому перевірено все, що можна перевірити без них.

## Що перевірено 05.10.2026

**Підпис запиту.** `temu_client.sign()` дає `4CCF219942D4180C6DDA3CE36C1B838F` на прикладі з
документації Temu, тобто збігається з їхнім алгоритмом символ у символ:
MD5(app_secret + ключі за ASCII як `ключзначення` + app_secret), великими літерами.
Вкладені об'єкти серіалізуються JSON без пробілів, і тіло запиту має бути тим самим рядком.

**Живий шлюз EU** `https://openapi-b-eu.temu.com/openapi/router`, 6 запитів з вигаданими ключами:

| Запит | Очікував за документацією | Відповів шлюз |
|---|---|---|
| порожнє тіло | 3000002 no type | 3000002, так само |
| лише `type` | 3000010 no timestamp | **3000025 no app_key** (app_key перевіряється раніше) |
| неіснуючий метод | 3000003 type not exists | 3000003, так само |
| старий timestamp | 3000012 expired | **4000000** (до timestamp не дійшов, спершу ключ) |
| вигаданий app_key | 3000026 app_key not exists | **4000000 "The application information query is abnormal"** |
| без `sign` | 3000040 no sign | 3000040, так само |

Відповідь завжди HTTP 200, у тілі `success`, `errorCode`, `errorMsg`, `requestId` (префікс `eu-`),
час відповіді ~50 мс (перший запит ~490 мс).

**Висновок для коду:** 4000000 у документації означає системну помилку, яку варто повторити, але
на невідомий ключ шлюз повертає саме його. Клієнт тепер не повторює 4000000 з текстом
"application information query is abnormal", інакше хибні ключі давали б 3 запити замість одного.

## Що знайдено в документації

- Хости: US `openapi-b-us`, EU `openapi-b-eu` (DE, IT, FR, ES, UK...), global `openapi-b-global` (MX, JP...).
- Лише POST, JSON. Ліміт за замовчуванням 20 запитів/с на `app_key`, помилка 4000004.
- Замовлення: `bg.order.list.v2.get`, `bg.order.detail.v2.get`. Залишки: `bg.local.goods.stock.edit`,
  `temu.local.goods.sku.stock.query`.
- Доступ: продавець у Seller Center авторизує застосунок (портал розробника для ЄС
  `partner-eu.temu.com`), вибирає дозволи (замовлення, залишки, адреси) і передає `access_token`.
  `access_token` прив'язаний до `app_key`; прострочений або перевипущений дає 3000034.

Джерело тексту документації: копія порталу partner.temu.com у
github.com/opastorello/temu-api-docs (неофіційна). Підпис і коди помилок перевірені
на живому шлюзі, тож у цих місцях копія відповідає дійсності, крім зазначених розбіжностей.

## Чого не перевірено (потрібні ключі продавця)

- реальні поля замовлення в `bg.order.list.v2.get` (варіанти, комплекти, статуси скасування);
- чи дає Temu продавцю з Іспанії доступ до API і скільки чекати схвалення застосунку;
- поведінка `bg.local.goods.stock.edit` (повна заміна залишку чи дельта).
